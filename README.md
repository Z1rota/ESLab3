# Лабораторная 3: змейка с FreeRTOS

Проект для SDK-1.1MC.427, STM32F427VIT6. Базовый код восстановлен вручную;
генерация CubeMX для сборки не нужна. HAL, CMSIS и FreeRTOS взяты из установленного
STM32Cube_FW_F4_V1.28.0 и включены в проект.

## Как собрать и запустить

1. В STM32CubeIDE обновить `svaga` (F5), закрыть и снова открыть проект.
   Если IDE по-прежнему видит только IOC-проект, перезапустить IDE. При необходимости
   удалить проект **только из списка workspace, без удаления файлов**, затем
   File → Import → General → Existing Projects into Workspace → выбрать папку `svaga`.
2. Выбрать Debug, Project → Build Project. Результат: `Debug/svaga.elf`, `Debug/svaga.hex`.
3. Подключить стенд к USB DBG. Run → Debug Configurations → `svaga Debug`.
   Конфигурация использует OpenOCD и `SDK11M.cfg` для встроенного FTDI/JTAG.
   После остановки на `main` нажать Resume (F8).
4. На OLED появится `5 START SCORE 000`. Нажать 5.

Исходный `svaga.ioc` сохранён без изменений, но **не описывает добавленные I2C,
клавиатуру и игровые задачи**. Не нажимать Generate Code поверх этой реализации:
он может перезаписать вручную восстановленные файлы. Менять версию CubeMX не нужно.
Резервная копия исходного описания проекта: `.project.original`.

Альтернативная сборка из PowerShell в папке проекта:

```powershell
.\build.ps1
# Если IDE установлена в другом месте:
.\build.ps1 -CubeIDE 'D:\CubeIDE\STM32CubeIDE_1.19.0\STM32CubeIDE'
```

Этот вариант создаёт `Build/svaga.elf`, `.hex`, `.bin`; адрес загрузки BIN — `0x08000000`.
Скрипт сборки плату не прошивает. Конфигурация отладки подготовлена по примеру
производителя, но подключение к физической плате в ходе разработки не проверялось.

## Управление

Используется матричная клавиатура 4×3 стенда, не аналоговый джойстик.

| Кнопка | Действие |
| --- | --- |
| 2 / 4 / 6 / 8 | Вверх / влево / вправо / вниз |
| 5 | Начать; пауза / продолжить; повторить после проигрыша или победы |
| # | Начать заново в любой момент |

Расположение считается как у телефонной клавиатуры: 1–2–3 сверху, *–0–# снизу.
Если кнопки не подписаны: верхняя средняя — вверх; второй ряд — влево/пауза/вправо;
третий ряд, средняя — вниз; нижняя правая — перезапуск.

Поле 30×12 клеток. Шаг каждые 300 мс, еда размером 3×3 пикселя увеличивает длину и счёт.
Удар о границу или тело завершает игру; заполнение поля означает победу.
Разворот на 180° запрещён, за один шаг принимается не более одного поворота.
Нажатия подавляют дребезг; одновременные кнопки игнорируются.

## Устройство программы — для защиты

| Задача | Приоритет CMSIS | Работа |
| --- | --- | --- |
| InputTask | AboveNormal | Опрос клавиатуры примерно раз в 20 мс; фильтрация; очередь команд |
| GameTask | Normal | Обработка команд каждые 20 мс; движение раз в 300 мс; публикация состояния |
| DisplayTask | BelowNormal | Получение снимка состояния и вывод OLED |

`commands` — очередь на 8 команд. `frames` — очередь длиной 1 со свежим снимком
состояния, обновляемая через `xQueueOverwrite`. Игровое состояние принадлежит
только GameTask; экран получает копию, поэтому частично обновлённой змейки не видит.
InputTask и DisplayTask используют один I2C1, защищённый мьютексом с наследованием
приоритета. Экран освобождает шину после каждой страницы, чтобы дать клавиатуре
возможность её использовать. Потерянные при переполнении очереди команды не блокируют ввод.

Задачи создаются через CMSIS-RTOS v1 (`osThreadDef`, `osThreadCreate`), очереди и
мьютекс — через API FreeRTOS. `vTaskDelayUntil` задаёт период опроса и игры.
У OLED при 100 кГц полный кадр занимает около 100 мс, поэтому частота экрана ниже
частоты игрового цикла. При задержке экрана очередь оставляет самый свежий кадр.

| Файл | Назначение |
| --- | --- |
| Core/Src/main.c | HSI 16 МГц, GPIO, I2C1, USART6, TIM1 и запуск ОС |
| Core/Src/freertos.c | Три задачи, две очереди, мьютекс, обработка ошибок ОС |
| Core/Src/snake.c | Логика игры без зависимости от HAL/RTOS |
| Core/Src/board_io.c | PCA9538, OLED, пиксели и компактный шрифт |
| Core/Inc/FreeRTOSConfig.h | Настройки ядра, heap 24 КБ, проверки стека |
| STM32F427VITx_FLASH.ld | 2 МБ Flash и 192 КБ обычной RAM; CCM не используется |

## Подключения

| Сигнал | Подключение |
| --- | --- |
| I2C1 SCL / SDA | PB8 / PB9 |
| OLED 128×64 | I2C, адрес 0x3C (0x78 в HAL) |
| Клавиатура PCA9538 | I2C, адрес 0x71 (0xE2 в HAL) |
| USART6 TX / RX | PC6 / PC7, 115200 8N1; настроен, игра его не использует |
| LED1 / LED2 / LED3 | PD13 / PD14 / PD15 |
| Отладка | JTAG: PA13–PA15, PB3, PB4 не переназначаются |

LED1 показывает активную игру, LED2 — паузу, LED3 — проигрыш либо ошибку дисплея.
Неустранимая ошибка инициализации/стека останавливает выполнение в Error_Handler.
HAL использует TIM1 с тиком 1 мс, FreeRTOS использует SysTick с тиком 1 мс.
Тактовая частота оставлена 16 МГц от HSI, как в исходном IOC: внешний кварц не нужен.

При пустом экране сначала проверить питание/перемычки стенда, I2C PB8/PB9 и адрес
OLED. Если экран работает, а кнопки нет — подключение клавиатуры и адрес 0x71.
Для иной ревизии подключения и таблица кнопок меняются в `main.c` и `board_io.c`.

## Проверки

Логика из настоящего `snake.c` скомпилирована в ARM-код и выполнена в Unicorn:
движение, запрет обратного и двойного поворота, пауза, перезапуск, рост, размещение
еды, стены, столкновение с телом, вход в освобождаемый хвост, заполнение поля,
1000 начальных состояний генератора еды. Тесты: `tests/test_snake.c`.

Повторить при установленном Python и пакете `unicorn`:

```powershell
python tests/run_tests.py
```

Эмуляция проверяет игровую логику, а не реальные I2C, OLED и планирование на плате.
Физическая проверка: старт → поворот → еда → пауза → продолжение → стена → повтор.

## Источники

- Методичка МК3, слайд 48: змейка или тетрис, обязательное использование FreeRTOS.
- Примеры производителя: https://github.com/lmtspbru/SDK-1.1M — SDK_OLED (OLED/I2C),
  SDK_Keyboard (адрес и сканирование PCA9538), SDK_FreeRTOS (метаданные IDE и отладчик).
- В примере OLED комментарий упоминает PB6/PB7, но исполняемый код задаёт PB8/PB9;
  здесь использована именно фактическая конфигурация.
- HAL/CMSIS/FreeRTOS сохранены с исходными заголовками и доступными лицензиями.
  Игра, задачи, драйверный слой и шрифт написаны для этой лабораторной.
